1. The learning map

Imagine an email that says: “Maya Chen joined Acme Health in Seattle on 12 May.” A computer can first split it into tokens. Sequence labeling then assigns a label to each token or finds spans made from multiple tokens.

POS asks: “What grammatical role is this word playing here?” NER asks: “Is this word part of a named entity, and what kind?”

Both tasks add structure to unstructured text. That structure can help other systems search, translate, summarize, answer questions, or interpret speech.

2. What is sequence labeling?

A sequence is an ordered series—in this case, the words or tokens of a sentence. In sequence labeling, a model reads that sequence and assigns one or more labels to its parts, while using clues from nearby words and the larger context.

For “Maya Chen joined Acme Health,” the word “Maya” may look like a person’s name, while “joined” provides context that a company or team may follow. Labels are not just attached by looking at each word in isolation.

Memory cue: sequence labeling = keep the text in order, then attach labels along it.

3. POS tagging: identify each word’s grammatical job

Part-of-speech (POS) tagging assigns a grammatical category to each word, such as noun, verb, adjective, adverb, pronoun, preposition, or determiner. Fine-grained tag sets add details such as tense, number, or whether a noun is a proper name.

Context resolves ambiguity

The same spelling can have different grammatical roles. In “the sitting area”, sitting describes the area; in “I was sitting”, it is part of the verb. A tagger uses the word’s context to choose a likely role.

Likewise, read has different pronunciations in “I read every day” and “I read yesterday.” A POS tagger can help a speech system distinguish present from past tense.

Why POS tagging is useful

  • Machine translation: knowing that a word is an adjective can help a translation system place it correctly in another language.
  • Text-to-speech: grammatical context can help choose pronunciation, as with present and past forms of read.
  • Speech transcription evaluation: POS information can be compared between a reference transcript and a system’s output.
  • Downstream NLP: POS tags can provide useful features to other language-processing tasks, including some NER systems.
Memory cue: POS labels the word’s job, not its real-world identity.

4. NER: find and classify names

Named Entity Recognition (NER) identifies text spans that refer to named things and assigns each span a category. Common categories include:

PER

A person, such as “Maya Chen.”

LOC

A location, such as “Mount Rainier.”

ORG

An organization, such as “Acme Health.”

GPE

A geopolitical entity, often a country, city, or state, such as “Seattle” or “France.”

Other labels

Some tag sets include dates, times, money, products, events, or a general “miscellaneous” type. The exact categories depend on the task and dataset.

NER is more than spotting capital letters. It must decide where an entity begins and ends, and what it refers to in context. “Franklin” might be a person or a place. “United Airlines” is one organization name made of two words.

BIO / IOB tags mark entity boundaries

A common format assigns a tag to each token:

  • B- means the Beginning of an entity span.
  • I- means a token Inside the same entity span after its beginning.
  • O means Outside any entity.

The category follows the boundary marker: B-PER begins a person span; I-PER continues it; B-ORG begins an organization. Some formats are called BIO or IOB; implementations may differ in tag conventions, but the key purpose is to make the entity boundaries explicit.

Memory cue: B = begin, I = inside, O = outside. Use the entity type to say what kind of name it is.

Why NER is useful

NER can turn a paragraph into structured facts for search, question answering, summarization, and information extraction. A travel app might extract city names and dates from a message; a news search tool might index people and organizations separately.

6. How do models produce the labels?

The module introduces a traditional tagger and encoder-based transformer models. In practice, the system is trained or fine-tuned using examples where people have already assigned the desired tags.

Average Perceptron tagger

The lecture describes NLTK’s POS tagger as an average-perceptron model. At a high level, a perceptron scores possible tags using learned weights and word/context features, then adjusts its weights when predictions disagree with training labels. NLTK’s ready-to-use tagger hides much of this training detail.

NER chunker

The lecture presents an NLTK named-entity chunker that uses a Maximum Entropy classifier. It can use features such as words and POS tags to identify entity chunks, then represent the chunks in BIO/IOB form.

BERT / transformer token classifier

A pretrained transformer can be fine-tuned to predict a tag for each token. Context helps distinguish ambiguous words. BERT may split a name into subword pieces, so tools need to align model tokens back to the original words or entity spans.

Performance depends on the examples and label conventions used to train the model. A name or term rarely seen during training may be split oddly or mislabeled. Fine-tuning on relevant, representative data can help, but results should still be checked on examples that reflect the real task.

Important: the lecture’s model outputs illustrate behavior on a particular example; they are not a guarantee that every model will make the same predictions on all text.

7. Self-check

1. What is the main difference between POS tagging and NER?

POS identifies each word’s grammatical role. NER locates spans that name entities and classifies them, such as person, organization, or place.

2. Why might “sitting” receive different POS tags in two sentences?

Its role depends on context. In “the sitting area” it modifies a noun; in “I was sitting” it functions as part of a verb phrase.

3. In BIO tagging, what does I-ORG mean?

The token is inside or continues an organization entity span whose first token was marked B-ORG.

4. Why does NER need boundary tags?

Many names contain several words. Boundary tags help show where one entity begins and which following words belong to that same name.

5. Could “Franklin” be tagged differently in different sentences?

Yes. It could refer to a person or to a place. NER uses context and learned patterns to infer the likely entity type.

6. Why might a BERT-based tagger split an unfamiliar name?

Many transformer tokenizers use subword pieces. If a name is uncommon, it may be represented as several pieces; the system must align those pieces with the original word and label correctly.

Quick recall: POS = grammatical job; NER = named span and category; BIO = mark where each entity begins, continues, and ends outside.

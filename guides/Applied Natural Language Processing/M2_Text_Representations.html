1. The learning map

Computers and machine-learning algorithms work with numbers. Text begins as words, so we need a text representation: a consistent way to turn words or documents into numbers.

The three methods build on one another: one-hot encoding gives a word an identity vector; Bag of Words (BoW) counts words in a document; TF-IDF keeps the document structure but adjusts counts so common words carry less weight.

Imagine a library that wants to search support tickets. A computer cannot directly compare the raw sentences the way a person reads them. These representations make documents measurable so a program can search, compare, group, or classify them.

2. A few useful terms

Corpus

A collection of documents, such as all the reviews or help-desk tickets being studied.

Token

A unit of text selected by a tokenizer—often a word. For simple examples, spaces separate the tokens.

Vocabulary

The unique tokens chosen from the corpus. Each vocabulary item gets its own consistent position in a vector.

Vector and dimension

A list of numbers is a vector. If the vocabulary has D terms, each document vector has D positions (dimensions).

Sparse

A vector or matrix is sparse when most entries are zero. In text, each document usually uses only a small fraction of the full vocabulary.

Document-term matrix

A table whose rows represent documents and whose columns represent vocabulary terms. Each cell stores a value for a word in a document.

3. One-hot encoding: give each word an ID card

First, choose an ordered vocabulary. Each individual word becomes a vector filled with zeros, except for a single 1 in that word’s assigned position.

For the vocabulary [tea, coffee, cocoa]:

tea → [1, 0, 0]
coffee → [0, 1, 0]
cocoa → [0, 0, 1]

The vector position acts like the word’s ID number. A sentence can be represented as a sequence of these word vectors. If instead we collapse the sequence into one document vector, we can mark which vocabulary words appear; that single vector does not preserve the order of the words.

Why it is useful

It is simple and clearly identifies which vocabulary item a token represents.

Why it can be costly

Every vector needs one position per vocabulary item. A vocabulary of 100,000 words means very long vectors, most entries of which may be zero.

What it does not know

Each word is treated as unrelated to every other word. “Coffee” and “tea” are no closer than “coffee” and “volcano.”

Memory cue: one-hot gives each word one bright spot in a long row of zeros.

4. Bag of Words: count the words in a document

One-hot encoding identifies a word. Bag of Words summarizes a whole document by counting how many times each vocabulary word occurs. It treats the document like a bag of word tiles: it remembers which tiles and how many, but not their order.

Suppose the vocabulary is [tea, coffee, cocoa]:

DocumentBoW vectorWhat it means
tea coffee tea[2, 1, 0]“tea” occurs twice, “coffee” once, “cocoa” not at all.
coffee cocoa[0, 1, 1]“coffee” and “cocoa” occur once each.

For N documents and a vocabulary of D terms, the document-term matrix has N rows and D columns. A fixed vocabulary gives every document vector the same length, even if the original documents have different lengths.

What is lost? Word order and grammar. “Dog bites person” and “person bites dog” contain the same words, so a simple count vector cannot tell who did the biting. BoW also gives a common word and a distinctive word equal weight when both occur once.
Memory cue: Bag of Words is a word-count shopping list: it records what and how many, not where.

5. TF-IDF: give distinctive words more weight

Raw counts can overvalue words that appear in almost every document. TF-IDF (Term Frequency–Inverse Document Frequency) gives a word a larger weight when it is frequent in one document but less common across the whole collection.

TF: Term Frequency

How much this term appears in this document. A simple normalized version divides its count by the total number of tokens in the document.

IDF: Inverse Document Frequency

How uncommon the term is across the corpus. A term that occurs in every document has little power to distinguish one document from another.

TF(t, d) = count of t in d / total token count in d
IDF(t, D) = log( number of documents N / number of documents containing t )
TF-IDF(t, d, D) = TF(t, d) × IDF(t, D)

The lecture’s example uses log(N / DF), where DF is the number of documents containing the word. If a word occurs in every document, then N / DF = 1, and log(1) = 0: that ubiquitous word receives no distinguishing weight in this version. Libraries may use smoothed formulas or other conventions, so check which formula a tool implements.

Interpretation: a high TF-IDF score means “this word is relatively characteristic of this document in this collection.” It does not mean the word is universally important or that the computer understands its meaning.
Memory cue: TF asks “often here?”; IDF asks “rare across the collection?”; TF-IDF combines both.

6. Worked real-world example: find delivery-delay tickets

Imagine a help desk wants to retrieve messages about delivery problems. Consider these short example documents:

  • D1: “password reset reset”
  • D2: “password login”
  • D3: “delivery late”

This tiny collection is only an illustration. It lets us see how the numbers are built—not a measured result from the course.

Step A: build a shared vocabulary and count words

Use the vocabulary [delivery, late, login, password, reset]. A document’s BoW vector has one slot per term, in exactly that order.

Documentdeliverylateloginpasswordreset
D100012
D200110
D311000

Step B: calculate one TF-IDF score

For “reset” in D1, the term occurs twice among three tokens, so TF = 2/3. “Reset” appears in only one of the three documents, so using the lecture’s formula IDF = ln(3/1) ≈ 1.099. Its TF-IDF weight is:

TF-IDF(reset, D1) = (2/3) × ln(3) ≈ 0.732

By contrast, “password” occurs in two of the three documents, so its IDF is smaller: ln(3/2) ≈ 0.405. In D1 its TF is 1/3, giving a TF-IDF weight of about 0.135. The distinctive word “reset” weighs more for D1 than the shared word “password.”

In a real help-desk archive, this weighting can help a search system recognize that “late” or “delivery” is more useful for finding delivery tickets than generic words appearing in nearly every ticket.

7. Compare the three methods

MethodWhat it representsWhat its values sayMain limitation
One-hotUsually an individual token (or a sequence/matrix of token vectors)Which vocabulary item this token isVery wide, sparse vectors; no similarity or meaning between words
Bag of WordsA documentHow many times each vocabulary term occursIgnores word order and treats all terms without corpus-level importance weighting
TF-IDFA documentHow frequent a term is here, adjusted for how widespread it is elsewhereStill ignores word order and deeper meaning; depends on the corpus

How to remember the progression

  1. One-hot: “Which word is this?”
  2. BoW: “Which words, and how many, are in this document?”
  3. TF-IDF: “Which words make this document stand out from the others?”
Shared limitation: all three are discrete, vocabulary-based representations. Basic BoW and TF-IDF do not preserve word positions or understand synonyms and context. “Great” and “excellent” remain different columns, and “not helpful” may look like counts of “not” and “helpful” without understanding their combined meaning.

These methods remain useful when you want a transparent, relatively simple baseline—for example, keyword search, document retrieval, clustering, or traditional text classification. They are not the only way to represent language; later course topics include word embeddings and transformer models.

8. Self-check

1. If a vocabulary has 8,000 terms, how long is a basic BoW vector for one document?

It has 8,000 positions—one for every vocabulary term—regardless of how short the document is.

2. What does the BoW vector [2, 0, 1] mean for vocabulary [tea, coffee, cocoa]?

The document contains “tea” twice, “coffee” zero times, and “cocoa” once.

3. Does a high TF-IDF score mean the word is important in every document?

No. It means the term is relatively frequent in that particular document and uncommon across the collection used to compute IDF.

4. Why does a word found in every document have IDF equal to zero in the lecture formula?

If it occurs in all N documents, then DF = N, so log(N/DF) = log(1) = 0. It does not help distinguish one document from another under this formula.

5. Which methods preserve the order of words in a document?

Basic BoW and TF-IDF do not. One-hot vectors for each token can be kept as an ordered sequence or matrix, but a single pooled document vector does not retain word order.

6. A search result should favor terms that occur often in one ticket but rarely in the archive. Which representation fits that goal?

TF-IDF, because it combines within-document frequency with inverse collection-wide document frequency.

Quick recall: one-hot identifies a word; BoW counts words; TF-IDF counts words while down-weighting terms shared across many documents. All three simplify or discard context in different ways.

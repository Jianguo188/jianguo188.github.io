1. The learning map

Suppose a company has thousands of customer messages but no labels saying what each message is about. Topic modeling can help surface recurring themes—such as delivery, billing, or account access—without first asking a person to label every message.

Core idea: topic modeling looks for patterns in which words appear together across documents. It can organize text into hidden themes, but people usually interpret and name the themes afterward.

This module introduces two approaches:

LSI (Latent Semantic Indexing)

Uses Singular Value Decomposition (SVD) to compress a document-term matrix into a smaller latent concept space.

LDA (Latent Dirichlet Allocation)

Models each document as a mixture of topics and each topic as a distribution over words.

2. Topic modeling basics

Unsupervised learning means the algorithm is not given the correct topic label for every document. Instead, it searches the text for structure. A topic is not automatically a human-written label like “billing”; it is first represented by patterns or probabilities over words.

Start with a document-term matrix

A document-term matrix has one row per document and one column per vocabulary term. A cell may contain a count, weight, or other numeric value indicating how a term relates to a document.

Here, Messages 1 and 3 share delivery-related words, while Message 2 uses account-access words. Topic models try to find patterns like these across a much larger collection.

Memory cue: the matrix is the map; topic modeling finds groups of columns and rows that tend to belong together.

3. LSI: compress documents into latent concepts

Latent Semantic Indexing (LSI) looks for hidden associations between terms and documents. The module uses SVD to decompose the document-term matrix into lower-dimensional factors.

Let A be an n × d document-term matrix: n documents by d terms. Its SVD can be written:

A ≈ Uk Σk VkT
  • Uk describes how documents relate to the selected latent concepts.
  • Σk contains the strength of the retained dimensions, ordered from stronger to weaker.
  • VkT describes how terms relate to those concepts.
  • k is the number of retained latent dimensions; choosing a smaller k compresses the original matrix.

Think of a concept as a weighted group of related terms. A hidden “database” concept might give higher weights to data, system, and retrieval. The model does not know that the concept should be called “database”; a person can assign a readable name after inspecting the term patterns.

Why latent concepts help search

Two documents may be related even if they do not use exactly the same words. By mapping terms and documents into a shared concept space, LSI can find a document about “information retrieval” for a query containing “data,” even when one exact keyword is missing.

Trade-off: reducing dimensions loses some information. A basic document-term matrix also does not preserve word order, so LSI cannot fully understand sentence structure, negation, or all meanings of a word.
Memory cue: LSI uses SVD to make a smaller “concept map” linking terms and documents.

4. LDA: documents mix topics, and topics mix words

Latent Dirichlet Allocation (LDA) is a probabilistic topic model. Before fitting it, choose a topic count K. LDA then estimates two useful distributions:

Document-topic distribution

For each document, how much is it associated with each topic? A message might be 70% delivery, 20% refunds, and 10% account access.

Topic-word distribution

For each topic, which words are likely? A delivery topic might assign higher probability to “package,” “tracking,” and “arrived.”

In the lecture’s generative explanation, a document has a distribution over topics; each word gets a topic according to that distribution; then the word is drawn from the selected topic’s word distribution. The algorithm tries to find distributions that explain the observed documents well.

Dirichlet distributions are probability distributions over probability distributions. In practical terms, they act as priors that influence whether a document tends to use many topics or only a few, and whether a topic tends to use many words or only a few. These influences are controlled by parameters often written α and β (software may call the word-topic prior eta).

The slides describe Gibbs sampling as one way to iteratively revise word-topic assignments. Some software packages use other inference methods, such as variational inference; you do not need to implement the inference algorithm by hand to use an LDA library.

Topics need human interpretation

LDA initially labels topics with IDs such as Topic 0 and Topic 1. A person inspects each topic’s highest-probability words and representative documents to decide whether it resembles “sports,” “billing,” or something else. A topic’s label is an interpretation, not a supervised answer supplied to the model.

Important setup choice: basic LDA requires choosing K in advance. If K is too small, distinct themes may be merged; if too large, a theme may be split into several less coherent topics. Try plausible values and assess whether the results are useful.
Memory cue: LDA answers two questions: “Which topics are in this document?” and “Which words describe each topic?”

6. Python examples: try LDA and LSI

The following self-contained example uses invented support tickets. It trains both models and prints the strongest words for each discovered component/topic. The particular output can vary with the text, settings, and library version; the topic names in comments are human interpretations, not model-provided truths.

Install scikit-learn if needed with python -m pip install scikit-learn. Save the code as topic_models_demo.py and run python topic_models_demo.py.

from sklearn.decomposition import LatentDirichletAllocation, TruncatedSVD
from sklearn.feature_extraction.text import CountVectorizer, TfidfVectorizer

# Illustrative customer-support messages; no labels are provided to the models.
documents = [
    "package delivery is late tracking number has not updated",
    "my parcel arrived late and delivery tracking is confusing",
    "please refund my payment the order was cancelled",
    "I need a refund because I was charged twice for my order",
    "I cannot reset my password and cannot log in",
    "login failed after I changed my account password",
    "the delivery package arrived but I want to return the item",
    "how can I update my account email and password",
]

# LDA typically uses nonnegative word counts.
count_vectorizer = CountVectorizer(stop_words="english")
counts = count_vectorizer.fit_transform(documents)
count_terms = count_vectorizer.get_feature_names_out()

lda = LatentDirichletAllocation(
    n_components=3,       # choose K before fitting
    random_state=7,        # makes this example more reproducible
    learning_method="batch",
    max_iter=30,
)
document_topic = lda.fit_transform(counts)

print("LDA: likely words for each topic")
for topic_id, weights in enumerate(lda.components_):
    top_ids = weights.argsort()[-6:][::-1]
    top_words = [count_terms[i] for i in top_ids]
    print(f"Topic {topic_id}: {', '.join(top_words)}")

print("\\nLDA: topic mixture for each ticket")
for doc_id, distribution in enumerate(document_topic, start=1):
    print(f"Ticket {doc_id}: {distribution.round(2)}")

# LSI-style concept space: TF-IDF followed by truncated SVD.
tfidf_vectorizer = TfidfVectorizer(stop_words="english")
tfidf = tfidf_vectorizer.fit_transform(documents)
lsi = TruncatedSVD(n_components=3, random_state=7)
document_concepts = lsi.fit_transform(tfidf)
term_concepts = lsi.components_
tfidf_terms = tfidf_vectorizer.get_feature_names_out()

print("\\nLSI: strongest words for each latent component")
for component_id, weights in enumerate(term_concepts):
    top_ids = weights.argsort()[-6:][::-1]
    top_words = [tfidf_terms[i] for i in top_ids]
    print(f"Component {component_id}: {', '.join(top_words)}")

print("\\nLSI: document coordinates in concept space")
for doc_id, coordinates in enumerate(document_concepts, start=1):
    print(f"Ticket {doc_id}: {coordinates.round(2)}")

How to read the output

  • For LDA, the printed words summarize each topic; the row of document-topic values shows each ticket’s estimated topic mixture. The values in a row are proportions and sum approximately to 1.
  • For LSI, each ticket is represented by coordinates in the retained SVD concept dimensions. Component weights indicate which terms contribute to those dimensions.
  • Topic/component IDs have no inherent names or ranking such as “Topic 1 is always delivery.” Inspect top words and sample documents before assigning a human-readable label.
Feature choice matters: LDA in this example receives count features, while LSI receives TF-IDF values. For your own data, follow the assumptions of the implementation, fit vectorizers on training data only when evaluating a predictive pipeline, and check that preprocessing has not removed important terms.

7. A practical topic-modeling workflow

  1. Define the purpose. Are you exploring a large archive, improving search, or summarizing common themes?
  2. Prepare documents. Remove empty or irrelevant records, choose tokenization and stop-word handling, and preserve useful domain terms.
  3. Build features. Create a document-term matrix. Use the representation expected by the chosen method.
  4. Try a sensible range of settings. For LSI choose a retained dimension count; for LDA try plausible topic counts and, if appropriate, prior settings.
  5. Inspect both sides. Review top words per topic and representative documents per topic. A word list alone can be misleading.
  6. Check usefulness with people. Ask whether the topics are understandable and whether they help the real users’ task. Topic coherence metrics can assist, but they do not replace task-based review.
  7. Iterate and document. Adjust preprocessing or settings, then record the choices so results can be reproduced.
Quick recap: LSI = SVD concept space; LDA = document-topic and topic-word distributions; both discover patterns without labeled topic answers.

8. Self-check

1. Why is topic modeling called unsupervised?

The algorithm is not given a correct topic label for every document. It discovers patterns from the text features.

2. In LSI, what does SVD help create?

A lower-dimensional latent space relating documents and terms through shared concepts. A person interprets the dimensions after inspecting their strongest terms and documents.

3. What are the two main distributions returned by an LDA-style model?

A topic mixture for each document, and a word distribution for each topic.

4. Does LDA automatically know that a topic is “sports”?

No. It produces topic IDs and word probabilities. A person inspects the topic’s words and documents and may name it “sports.”

5. What can happen if the chosen topic count K is too small?

Distinct themes may be merged into the same topic. If K is too large, a theme may be split into multiple topics.

6. What should you inspect before trusting a discovered topic?

Its most probable words and representative documents, and whether people find it useful for the intended task. A short list of top words alone may be ambiguous.

Quick recall: LSI compresses a term-document matrix into latent concepts with SVD. LDA estimates topic mixtures for documents and word mixtures for topics. Neither discovers guaranteed “true” labels—inspect and validate the patterns.

Why Do We Need LSTM?

The problem with regular neural networks when processing sequences

The Problem: RNN Has a "Goldfish Memory"

Regular Recurrent Neural Networks (RNNs) process words one at a time, passing a hidden state from one step to the next — like a game of telephone. The problem? If the sentence is long, the early words get "forgotten" by the time the network reaches the end.

Real Example from Your Course

"I was born in Japan and lived there for 10 years and then moved to the US. My native language is ____."

  • The answer is Japanese — but it depends on remembering "Japan" from the start of the sentence.
  • An RNN, by the time it reaches the blank, has processed so many words that the signal from "Japan" has faded to almost zero.
  • This is called the vanishing gradient problem: during training, the error signal shrinks as it travels backward through many time steps.
Analogy

Imagine reading a 500-page book and being asked "What color was the car on page 3?" You'd struggle too! RNN is like a reader who can only remember the last few paragraphs clearly. LSTM is like a reader who takes notes and can flip back to page 3 anytime.

The Solution: LSTM = RNN + "Gates"

Long Short-Term Memory (LSTM) fixes the memory problem by adding gates — think of them as smart valves that control what information flows through and what gets discarded. Instead of one hidden state, LSTM adds a cell state — a dedicated "memory highway" that runs straight through the entire sequence.

RNN loses early information; LSTM preserves it via the cell state highway

The Cell State: Your Memory Highway

The most important part of LSTM is the cell state (written as C_t). Think of it as a conveyor belt that runs straight through the entire sequence. Information flows along it unchanged unless a gate specifically adds or removes something.

Analogy

The cell state is like a conveyor belt in a sushi restaurant: the sushi (information) keeps moving forward. The chef (gates) can add new sushi or remove old sushi at each station, but the belt itself never stops.

Key Tool The Sigmoid Function — the "volume knob" of every gate
sigmoid(x)  =  1 / (1 + e-x)
Sigmoid squashes any number into the range 0 to 1. This output acts like a slider:
0 = block everything (forget this info) 0.5 = partially keep (mix old & new) 1 = let everything through (keep this info)
Memory Aid

Sigmoid = Slider: think of it as a volume knob from 0 (mute) to 1 (full volume). Every gate uses a sigmoid to decide "how much" of something to keep.

Key Takeaways — Lesson 1

  • RNN forgets early words in long sequences (vanishing gradient)
  • LSTM adds a cell state — a memory highway that carries info across all time steps
  • Gates (using sigmoid) control what enters, stays, and leaves the cell state
  • LSTM is the go-to model for any task involving time or sequence (text, speech, etc.)

Inside the LSTM: The Four Gates

Forget, Input, Cell Update, and Output — each with a specific job

An LSTM unit receives two inputs at each time step: the current word (x_t) and the hidden state from the previous step (h_t-1). It uses these to update its internal memory (cell state) and produce a new hidden state (h_t). Four gates work together to make this happen.

🗑️

1. Forget Gate (F_t)

"What should I throw away?"
Looks at the current word + previous hidden state, outputs 0–1 for each piece of the old cell state. 0 = delete, 1 = keep.

📝

2. Input Gate (I_t)

"What new info should I write down?"
Decides which values to update. Uses sigmoid to pick what's important, and tanh to create candidate new values.

🔄

3. Cell State Update

"Combine old and new."
Multiply old state by forget gate (drop some), then add the new candidate weighted by input gate.

📤

4. Output Gate (O_t)

"What should I tell the next step?"
Decides what part of the cell state becomes the new hidden state, which is used for predictions and passed forward.

Analogy: The Notebook

Imagine maintaining a notebook while reading a story:

  • Forget Gate = Erasing outdated notes (crossing out "it's morning" when the story moves to evening)
  • Input Gate = Writing down new important details (a character's name just revealed)
    • Cell State = The notebook itself (continuously updated)
  • Output Gate = Deciding what to say aloud right now (summarizing the current situation)

The Math — Simplified

Don't panic! Here's the step-by-step with plain labels. Each step is just multiply or add.

Each step uses the same two inputs: current word (x_t) and previous hidden state (h_t-1). The "W" and "b" are learned weights and biases — the model's parameters it adjusts during training.

Step 1 Forget Gate — "What should I erase?"
f_t  =  sigmoid( W_f · [h_t-1,  x_t] + b_f )
Output is 0 to 1 for each cell. 0 = delete this info from memory. 1 = keep it as-is.
Step 2 Input Gate — "What new info should I write?"
i_t  =  sigmoid( W_i · [h_t-1,  x_t] + b_i )
c˜_t  =  tanh( W_c · [h_t-1,  x_t] + b_c )
i_t decides which values to update (0 = skip, 1 = update).
c˜_t generates the candidate new values, scaled between -1 and +1.
Step 3 Update Cell State — "Combine old and new"
C_t  =  ( f_t × C_t-1 )  +  ( i_t × c˜_t )
Left side (f_t × C_t-1): erase some old memory using the forget gate.
Right side (i_t × c˜_t): write in some new memory using the input gate.
Add them together → that's your updated notebook!
Step 4 Output Gate — "What do I pass to the next step?"
o_t  =  sigmoid( W_o · [h_t-1,  x_t] + b_o )
h_t  =  o_t × tanh( C_t )
o_t decides which parts of the cell state to output.
h_t is the new hidden state — passed to the next time step and used for predictions.
Blue = variables Orange = functions (sigmoid, tanh) Purple = operations (×, +) W = weight matrix  |  b = bias  |  · = matrix multiply
Memory Aid: FICO

Remember the gate order: Forget → Input → Cell update → Output. Like the credit score "FICO" — appropriate, because LSTM is all about scoring what's worth remembering!

What Does Each Gate See?

Worked Example

Sentence: "I was born in Japan and moved to the US."

When the LSTM processes the word "US":

  • Forget gate might partially forget "born" (less relevant now), but keep "Japan" (still important for the native language question)
  • Input gate records "US" as a new location fact
  • Cell state now holds: "person born in Japan, now in US"
  • Output gate passes a hidden state that encodes the current context

Key Takeaways — Lesson 2

  • Four gates: Forget (erase), Input (write), Cell State (the notebook), Output (speak)
  • Every gate uses the same inputs: current word (x_t) + previous hidden state (h_t-1)
  • Sigmoid (0–1) controls "how much"; tanh (-1 to +1) generates "what values"
  • The cell state is updated by: old × forget + new × input

GRU — The Streamlined Cousin

Gated Recurrent Unit: fewer gates, faster training, similar results

What is GRU?

GRU (Gated Recurrent Unit) is a simplified version of LSTM. It merges some gates together to reduce complexity, making it faster to train while still solving the same memory problem.

Analogy

If LSTM is a Swiss Army knife with 4 tools, GRU is a pocket knife with 2 tools. For most everyday tasks, the pocket knife is enough — and it's lighter to carry.

Feature LSTM GRU
Number of gates 3 (Forget, Input, Output) + Cell State 2 (Update, Reset)
Separate cell state? Yes (C_t) No — uses hidden state only
Update gate Forget + Input (separate) Combined into one "update" gate
Reset gate Output gate "Reset" gate decides how much past to forget
Training speed Slower (more parameters) Faster (fewer tensor operations)
Best for Very long sequences, complex patterns Shorter sequences, when speed matters
Rule of Thumb

Start with GRU for quick experiments (it trains faster). Switch to LSTM if your sequences are very long or the model isn't capturing long-range dependencies well.

Encoder-Decoder Architecture

How LSTM is used for translation: read in one language, write in another

The Two-Part Design

For tasks like translation, we need to read a sequence in one language and write it in another. This calls for a two-part architecture:

Encoder reads "How are you?" → context vector C → Decoder writes "Jak sie masz?"
Analogy

The encoder is like a stenographer at a meeting — listens to the full input and compresses it into a summary (context vector C). The decoder is like a translator who reads only that summary and writes the output language.

The Problem: Information Bottleneck

The encoder must compress the entire input sequence into a single vector C. If the input is long, this becomes a bottleneck — too much information squeezed into too small a space. The decoder then has to work from this lossy summary alone.

Example

Translating a 20-word sentence: the encoder must stuff all 20 words' meaning into one fixed-size vector. The decoder then unpacks it word by word. Early words in the decoder can't "look back" at specific input words — it only sees the compressed summary.

The Fix → Attention (next section)

Instead of forcing everything through one vector, what if the decoder could "pay attention" to all the encoder's hidden states and pick the most relevant ones for each output word? That's exactly what Attention does.

5

Attention Mechanism

Letting the decoder "look back" at every word — not just the summary

The Core Idea

Without attention, the decoder only sees the final encoder output (one compressed vector). With attention, the decoder can look at every encoder hidden state and decide which ones are most relevant for the current word it's translating.

Analogy

Without attention: you read a whole book, then try to answer questions from memory alone.
With attention: you can flip back to any page and re-read the relevant paragraph before answering each question.

How Attention Works — Step by Step

Step 1: Score every encoder hidden state

For the current decoder word, calculate an alignment score (e) for each encoder hidden state. This measures "how relevant is this input word to the output I'm producing right now?" A small feedforward neural network computes this score from the encoder hidden state + the decoder's previous hidden state.

Step 2: Convert scores to weights (softmax)

Pass all the raw scores through a softmax function, which converts them into percentages (they sum to 1). These are the alpha (α) weights — "how much attention to pay to each input word."

Step 3: Build a weighted context vector

Multiply each encoder hidden state by its alpha weight and sum them up. This produces the context vector (c_t) — a custom blend of all input information, tuned for the current output word.

Step 4: Decode using the context vector

Feed the context vector into the decoder LSTM, which produces the output word. Repeat for every output word — each gets its own custom context vector.

For each output word the decoder produces, attention runs this 4-step loop. s_t-1 = decoder's previous hidden state  |  h_i = each encoder hidden state

Step 1 Score every encoder state — "How relevant is this input?"
e_t,i  =  tanh( W · [s_t-1 ;  h_i] )
A small feedforward neural network takes the decoder's previous state and one encoder state, and produces a raw alignment score. Repeat for every encoder state i.
Step 2 Softmax → attention weights — "Convert scores to percentages"
α_t,i  =  softmax( e_t,i )
Softmax turns the raw scores into weights that sum to 1 (like percentages). A high score becomes a high α (alpha) = "pay lots of attention to this word."
Step 3 Weighted sum → context vector — "Blend the most relevant inputs"
c_t  =  Σi   α_t,i × h_i
Multiply each encoder state by its alpha weight, then add them all up. The result is a custom context vector tuned for the current output word — words with high alpha dominate, words with low alpha barely contribute.
Step 4 Decode → output word
y_t  =  LSTM_decoder( s_t-1,  y_t-1,  c_t )
The decoder LSTM uses the context vector c_t (plus its previous state and output) to produce the current output word. Repeat for every output word — each one gets its own freshly-computed context vector.

Example: Translating "How are you?" → Polish

Attention in Action

When the decoder is about to produce the Polish word "Jak" (meaning "How"), the attention weights might look like:

  • "How" → α = 0.80 (high attention — this is the word being translated!)
  • "are" → α = 0.15
  • "you" → α = 0.05

The context vector for "Jak" is mostly built from the hidden state of "How." When translating "sie" (≈ "are"), the weights shift to focus on "are." This dynamic focus is the essence of attention.

Attention focuses mostly on "How" when translating to "Jak" — the line thickness = attention weight

Types of Attention

TypeUsed InHow It Scores

Self-Attention Transformers (core mechanism) Attends to its own input sequence
Why This Matters

Self-attention (where a sequence attends to itself, not to an encoder) is the foundation of Transformer models like GPT and BERT. The attention mechanism you learned here is the direct ancestor of modern AI!

Key Takeaways — Lessons 4 & 5

  • Encoder-decoder: encoder reads input → context vector → decoder writes output
  • Problem: one vector can't hold all information from long inputs
  • Attention lets the decoder look at ALL encoder hidden states
  • Alpha weights (from softmax) determine how much each input word matters
  • Context vector = weighted sum of encoder states, custom-built per output word
  • Self-attention (a variant) is the core of Transformers

Quick Self-Check Quiz

Click each question to reveal the answer

Test Your Understanding

1. Why does RNN struggle with long sentences?
Because of the vanishing gradient problem — as the error signal travels backward through many time steps during training, it shrinks to near zero, making the network unable to learn from early words in a long sequence.
2. What does the cell state (C_t) do in LSTM?
It's the "memory highway" — a vector that carries information across all time steps. Gates can add or remove information, but the cell state itself flows mostly unchanged, preserving long-term memory.
3. What are the four components of an LSTM unit (in order)?
Forget Gate, Input Gate, Cell State Update, Output Gate. Remember: FICO!
4. What's the difference between sigmoid and tanh in LSTM?
Sigmoid outputs 0–1 (used in gates to decide "how much" to keep/forget). Tanh outputs -1 to +1 (used to generate candidate values and scale the cell state for output).
5. How is GRU different from LSTM?
GRU has only 2 gates (update + reset) instead of 3, and no separate cell state — it uses the hidden state for everything. This means fewer parameters and faster training, with similar performance on many tasks.
6. What problem does Attention solve in encoder-decoder?
The information bottleneck: without attention, the entire input must be compressed into one fixed-size vector. Attention lets the decoder access all encoder hidden states, weighting them by relevance for each output word.
7. What does the alpha (α) weight represent?
It's the attention weight (from softmax) that determines how much each encoder hidden state contributes to the context vector. Higher α = more attention to that input word.
8. What type of attention did you learn, and what's the other type used in Transformers?
This course covers additive attention (used in seq2seq LSTM models). Transformers use scaled dot-product attention and self-attention, which are more efficient variants.

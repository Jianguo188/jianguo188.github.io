1. The learning map

By the end, you should be able to explain what text classification does, describe how Naive Bayes makes a prediction, and choose sensible ways to check the model. The module’s story is:

Words → numbers → a predicted category → a careful check. A model cannot work directly with the meaning of a raw email; we first represent its words as measurable features.

First: represent text

Turn each document into a row of numbers describing which words occur and how often.

Then: learn patterns

Use examples with known labels to estimate which categories and words tend to occur together.

Finally: check mistakes

Compare predictions with known answers. Accuracy alone may conceal costly errors.

2. Classification basics

Learning from labeled examples

Supervised learning means learning from examples that already have answers. For instance, a training set might contain thousands of emails, each marked “spam” or “not spam.” The inputs are the emails; the known labels are the answers the model is learning to predict.

The computer learns a rule, often written f(x) → y: take input x and return a prediction y. Once learned, the rule can be used on a new email whose label is not yet known.

TaskWhat is predicted?Everyday example
ClassificationA category (discrete label)Spam or not spam; positive or negative review; one of ten handwritten digits
RegressionA number on a continuous scaleApartment rent from its size and number of bedrooms

How do words become numbers?

A common starting point is a bag-of-words representation. Build a vocabulary of the words seen in the data, then record each document using those vocabulary features. A document-term matrix has one row per document and one column per word or feature. Its entries can be word counts or weighted values such as TF-IDF.

Analogy: imagine a checklist with one column for “refund,” one for “winner,” and one for “meeting.” An email’s row records how often each word appears. The label (spam/not spam) is stored separately for training.

Bag-of-words mostly forgets word order. “Dog bites person” and “person bites dog” can look very similar if they contain the same words. This simple representation is useful, but it loses grammar and context.

Memory cue: classification chooses a class; regression estimates a number.

3. Naive Bayes: classify by combining clues

Naive Bayes is a probabilistic classifier. It estimates which label is most plausible by combining (1) how common that label is overall and (2) how likely the observed words are under that label.

Bayes’ rule in everyday language

P(label | words) ∝ P(words | label) × P(label)

Prior: P(label)

How common is this category before seeing this particular message? If 60 of 100 training reviews are positive, the positive prior is 0.60.

Likelihood: P(words | label)

How often do these words appear in examples with this category? “Excellent” may be more likely in positive reviews than negative ones.

Posterior: P(label | words)

After considering the words, how plausible is the category? The model compares this score across possible labels.

Bayes’ rule also includes P(words), the overall probability of seeing the words. For a single document being compared across labels, this denominator is the same for each candidate label. So we can compare the numerators—likelihood times prior—without calculating that shared denominator.

Why “naive”?

The method makes a simplifying assumption: given the label, each feature is treated as independent of the others. In a positive review, the model acts as though seeing “great” tells it nothing extra about whether “movie” will appear, once the category is known. Real language does not work so independently, which is why the assumption is called naive.

This shortcut turns a complicated probability for a whole document into a product of simpler word probabilities:

P(words₁, words₂, … | label) ≈ P(words₁ | label) × P(words₂ | label) × …

Worked example: a tiny review sorter

Illustrative toy counts for learning—not results measured by the course. Imagine 100 labeled reviews: 60 positive and 40 negative. In a small vocabulary, suppose the word “nice” appears 30 times among positive words and 5 times among negative words; “helpful” appears 20 and 7 times, respectively. Suppose the class totals are 52 positive word tokens and 37 negative word tokens. To avoid giving unseen words a probability of zero, use add-one (Laplace) smoothing for this illustration.

For a review containing “nice helpful,” compare:

Positive score = 0.60 × P(nice | positive) × P(helpful | positive)
Negative score = 0.40 × P(nice | negative) × P(helpful | negative)

With a three-word vocabulary, the smoothed estimates are:

P(nice | positive) = (30 + 1) / (52 + 3) = 31/55
P(helpful | positive) = (20 + 1) / (52 + 3) = 21/55
P(nice | negative) = (5 + 1) / (37 + 3) = 6/40
P(helpful | negative) = (7 + 1) / (37 + 3) = 8/40

The positive score is about 0.130; the negative score is 0.012. Since the positive score is larger, the toy classifier predicts positive. These are unnormalized comparison scores, not final probabilities that must add to 1.

Zero-count caution: without smoothing, one word never seen in a class can make the entire product zero. Add-one smoothing is a common fix for count-based Naive Bayes, although the lecture slides focus on the underlying count-based likelihood idea.

Generative versus discriminative models

Naive Bayes is called generative because it models how features might arise within each class (the class prior and the class-conditional word distribution). A discriminative model, such as logistic regression, focuses more directly on predicting the label from the features or separating one class from another. Both can be used to classify; they learn in different ways.

Memory cue: Naive Bayes asks, “If this were a positive review, how likely are these words?” Then it asks the same for the negative class and compares.

Strengths

  • Simple and quick to train from counts.
  • A useful baseline for text tasks such as spam detection and sentiment.
  • Can work well even though its independence assumption is imperfect.

Limitations

  • Bag-of-words may discard word order and meaning in context.
  • Word-independence is an approximation, not a fact about language.
  • Unseen words need careful handling, commonly with smoothing.

4. Evaluation: understand the kinds of mistakes

A model should be checked on examples that were not used to fit it. Compare its predictions with the known correct labels. A confusion matrix organizes those comparisons: rows show the actual class, columns show the predicted class, and the diagonal contains correct predictions. Off-diagonal cells show which categories are being confused.

Binary classification and the “positive” class

For two categories, choose which one counts as positive for the question at hand. In a spam filter, “spam” could be positive; in a disease-screening example, “disease present” could be positive. This choice determines the names of the error types.

Predicted positivePredicted negative
Actually positiveTrue positive (TP)
Correctly found a positive case		False negative (FN)
Missed a positive case
Actually negativeFalse positive (FP)
False alarm		True negative (TN)
Correctly rejected a negative case
Example: if “spam” is positive, a legitimate email wrongly sent to spam is a false positive. A spam email that reaches the inbox is a false negative.

Four useful measures

Accuracy

(TP + TN) / all examples

“What fraction of all predictions were correct?”

Precision

TP / (TP + FP)

“Of the items called positive, how many really were positive?” High precision means fewer false alarms.

Recall (sensitivity)

TP / (TP + FN)

“Of all actual positives, how many did we find?” High recall means fewer missed positives.

Specificity

TN / (TN + FP)

“Of all actual negatives, how many did we correctly leave negative?”

The F1 score combines precision and recall using their harmonic mean: 2 × precision × recall / (precision + recall). It is useful when both kinds of performance matter, but it does not replace understanding the application’s costs.

Memory cue: precision starts with the model’s positive predictions; recall starts with the actual positive cases.

Why accuracy can fool you

Suppose only 1 out of 100 transactions is fraudulent. A model that always predicts “legitimate” gets 99% accuracy—but it catches no fraud at all. Accuracy summarizes the count of correct answers; it does not tell you which mistakes happened or how costly they are.

In health screening, missing a real case (false negative) may be especially costly. In spam filtering, flagging an important legitimate message (false positive) may be especially costly. Choose measures with the real consequence in mind.

ROC curve and AUC

Many classifiers produce a score, then classify as positive only if the score passes a chosen threshold. Raising or lowering that threshold changes the balance between catching positive examples and generating false alarms.

  • True positive rate (TPR), also recall: TP / (TP + FN).
  • False positive rate (FPR): FP / (FP + TN).
  • A ROC curve plots TPR against FPR as the threshold changes.
  • AUC is the area under that curve; it summarizes ranking performance across thresholds.
Do not stop at AUC. A single summary can hide poor performance in the region or at the operating threshold that matters to you. Inspect the confusion matrix and the relevant precision/recall or false-alarm behavior too.

5. Put the ideas together

  1. Collect labeled examples. For example, emails marked by people as spam or legitimate.
  2. Convert the text into features. Build a vocabulary and represent each email as word counts or another numeric representation.
  3. Fit the classifier on training examples. Naive Bayes estimates class priors and word likelihoods from the labeled data.
  4. Predict labels for new examples. Compare a score for each candidate category.
  5. Evaluate on held-out examples. Make a confusion matrix and choose metrics that reflect the cost of mistakes.
  6. Improve and re-check. Adjust the representation, model, or decision threshold, then evaluate again on appropriate data.
One-line recap: turn words into features, learn label-specific word patterns, predict the most plausible label, and inspect what the model gets wrong.

6. Self-check: explain it in your own words

1. A model predicts whether a review is positive or negative. Is this classification or regression?

Classification: the output is a category. Predicting a star rating such as 4.2 would instead be a numerical regression task if treated as a continuous value.

2. In Naive Bayes, what is the prior and what is the likelihood?

The prior is how common a label is before examining the particular document. The likelihood is how probable the observed words are if that label is true.

3. What does the “naive” assumption say?

It treats features (such as word counts) as conditionally independent given the class label, allowing the joint word probability to be approximated by multiplying individual probabilities.

4. A spam filter misses spam and lets it into the inbox. What kind of error is this?

If spam is the positive class, this is a false negative: the actual example is positive, but the prediction is negative.

5. Which answers this question: “Of the actual positive cases, what fraction did we find?”

Recall (also called sensitivity): TP / (TP + FN).

6. Why might 99% accuracy still be poor?

If positives are rare, a model can get high accuracy by predicting the common negative class every time. It may still miss every positive case, so inspect class-specific metrics and the confusion matrix.

Quick recall: classification = choose a category; Naive Bayes = prior × word likelihoods; evaluation = inspect the errors, not just the accuracy.

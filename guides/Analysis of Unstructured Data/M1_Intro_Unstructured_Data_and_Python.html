M1: Intro to Unstructured Data and Python

1. The big picture

Businesses have plenty of information that does not arrive as a tidy spreadsheet: messages, reports, photos, audio, video, and web pages, for example. To analyze it, first decide what you want to learn, then extract and record the relevant information in a consistent form. Metadata keeps each result connected to its original source.

Because every source and question can differ, this work often needs a small, task-specific program. Python is useful because it is readable, flexible, and has a large ecosystem of packages for collecting, processing, and analyzing many kinds of data.

Memory cue: Decide the question → design the output → keep its source identity → process the material → check the result.

2. Key vocabulary

Structured data

Information already organized into predictable fields—often rows and columns—such as a customer table with one row per customer and columns for ID, region, and purchase date.

Unstructured data

Information that is not ready to analyze as a regular table or relational database. Examples include free-form text, images, audio, video, emails, and reports. It may contain patterns, but the useful fields have not yet been consistently extracted.

Metadata

“Data about data”: details that describe or identify a source record. For a report, this might include the organization, publication date, report type, and a unique source ID.

Schema

The planned shape of the output: its columns or fields, what each means, and the kind of value each should contain.

The lecture presents the estimate that 80% or more of business data is unstructured (with structured data around 20%). Treat this as an estimate used to motivate the topic—not a universal percentage that will hold for every organization, dataset, or date.

3. A practical workflow for structuring data

  1. Define the scope and question. What sources are included, and what do you want to find out? A vague question makes it hard to decide what to extract.
  2. Specify the desired output. Decide what one output row represents and what fields it needs. Choose the format before processing so your decisions are consistent.
  3. Plan metadata. Record enough source details to trace each output row back to the original item. A combination of fields should identify the source reliably; use a unique ID where possible.
  4. Plan collection and scale. Decide how to obtain the material. If there is a lot, consider processing it in batches so work can resume after stopping. Parallel processing—doing multiple items at once—may help, but adds complexity and is not always worthwhile.
  5. Write task-specific processing code. Collect and transform the source, then measure or classify what you need. Text sentiment or topic labels, for example, require choices suited to that task.
  6. Check the output and traceability. Confirm that the fields make sense and that each result can be associated with its source.
Important: Structuring is not just “putting text in a spreadsheet.” The question determines what to extract, and different tasks can need different schemas and processing methods.

4. Everyday example: understanding café reviews

Illustrative example—not a result measured in the course materials. Imagine a café wants to understand what customers praise or complain about in online reviews. The original reviews are free-form text, so they are not directly comparable like numeric sales records.

Start with a question

“What service themes appear in recent reviews, and are reviewers generally positive or negative?” Define which review sites and dates count as in scope.

Design a useful row

One row per review might include review_id, review_date, source, rating, text, and a derived sentiment_label.

Preserve the link

Keep the platform and its review ID (or another stable source reference). If a label seems wrong later, the analyst can find the original review and inspect it.

A review such as “The coffee was great, but I waited 20 minutes” contains more than one idea. A simple positive/negative label may hide that nuance. The business should decide whether it also needs fields for themes such as product quality and wait time, and should check automated labels rather than assuming they are always correct.

5. Why use Python?

Python is a high-level, general-purpose programming language. In plain language, it hides many low-level computer details and can be used for different kinds of work rather than being limited to one domain.

  • Readable syntax: the lecture emphasizes that Python code is designed to be comparatively easy to read and write.
  • Broad uses: Python can help collect, organize, transform, analyze, and visualize data, and is also used in areas such as web and app development.
  • Packages: reusable libraries add capabilities—from data analysis to natural-language processing (NLP) and machine learning—without requiring every tool to be built from scratch.
  • Good fit for customized workflows: scripts can combine collection and processing steps for a particular data source and question.
  • Interpreted workflow: the lecture contrasts running Python through an interpreter with compiling a program first. This is a useful introductory distinction; the exact execution details depend on the implementation and tools.
Not “best at everything”: Python’s popularity, readability, and ecosystem are strong advantages, but it is not automatically the fastest or best tool for every task. The lecture notes that some languages can be faster and that R may be preferable for some traditional statistical work. Choose based on the task, tools, and constraints.

6. Objects, attributes, methods, and functions

Python is object-oriented: programs work with objects, which are values that can be stored and manipulated. A useful mental model is to imagine a review as an object that has information about itself and actions that can be performed on it.

  • Attribute: information stored on an object—like a review’s rating or date.
  • Method: an operation associated with an object—like asking a text object to convert its letters to lowercase. In Python, methods are called with dot notation, such as some_text.lower().
  • Function: a reusable operation that can take inputs and return an output. Functions help divide a program into understandable steps. For example, a function could take a review and return a cleaned version.

Objects often have attributes and methods, but need not have both. A method is function-like but is associated with an object. A function itself is also an object in Python, though at this stage it is most useful to think of a function as a named, reusable operation.

Memory cue: Attribute = what it has; method = what it can do; function = a reusable operation you call.

7. Common mix-ups and limitations

  • “Unstructured” does not mean meaningless or totally pattern-free. It means the information is not already organized in the consistent tabular form needed for the planned analysis.
  • Do not choose columns after the fact without a question. The research question should guide the output design and processing choices.
  • Do not omit source identifiers. A derived label without enough metadata is difficult to audit, correct, or update.
  • Do not confuse metadata with the content itself. A review’s text is the content; its review ID, date, and platform help describe and identify that content.
  • More speed is not always better. Batching and parallelization are scale strategies; parallel work can bring extra coordination and troubleshooting.
  • Python’s popularity is not proof it is optimal for every job. Consider performance, existing expertise, available packages, and the nature of the analysis.

8. Quick recap

  1. Structured data is already organized in consistent fields; unstructured material needs task-specific processing before it is ready for the intended analysis.
  2. Plan the question and output schema first, then retain metadata so results can be traced to their sources.
  3. Python is a readable, flexible general-purpose language with a large package ecosystem, useful for customized data workflows.
  4. Objects can hold attributes and methods; functions package reusable steps of a program.

9. Self-check

Try answering each question before opening its explanation. The expandable answers use built-in HTML controls and work with a keyboard.

1. Why might a customer review need processing before it can be analyzed alongside many other reviews?

It is free-form text rather than a set of consistent fields. The analyst first needs to decide what information to extract and how to represent it consistently for the chosen question.

2. Name two useful pieces of metadata for a review dataset. What purpose do they serve?

A stable review ID and the source platform are two examples. Along with fields such as a date, they help identify the original review so an output can be traced and checked.

3. What should be decided before writing a script to structure a large collection of documents?

The scope and question, the desired output format and fields, metadata requirements, and the collection plan—including whether batches or parallel processing are warranted.

4. In the example some_text.lower(), what is lower?

It is a method associated with the string object some_text; it returns a lowercase version of the text.

5. Give one reason to choose Python and one reason not to assume it is always the best option.

Its readable syntax and broad package ecosystem make it useful for many custom data tasks. However, another language may be faster or better suited to a particular statistical workflow or existing environment.

1. The big picture

A small data-processing program often follows this pattern:

  1. Represent information with values such as text, numbers, and collections.
  2. Inspect or transform it with built-in functions and object methods.
  3. Choose what to do using conditions such as “is this value missing?” or “is this rating below the threshold?”
  4. Repeat the steps over records with a loop.
  5. Package reusable work in a function so the same rule can be applied consistently.
Memory cue: values hold the data; functions do a task; conditions choose a path; loops repeat a path over items.

2. Python building blocks

Values and variables

A variable is a name that refers to a value. The demo introduces common types: str for text, int for whole numbers, float for decimal numbers, and bool for True or False.

name = "Mina"         # str
orders = 4            # int
wait_minutes = 18.5   # float
is_open = True        # bool

print(type(wait_minutes))  # <class 'float'>

print() displays a value. type() helps check what kind of value you have. Formatted strings (f-strings) put variable values into readable text:

print(f"{name} has {orders} orders to review.")

Collections and objects

Python objects include individual values and containers such as lists, sets, tuples, and dictionaries. A list like ["A12", "B03"] stores an ordered sequence; a dictionary like {"A12": 18} maps a key to a value. The earlier W1 L2 guide covers those containers in more detail.

In a Jupyter notebook, the demo runs a cell with Shift+Enter. The result appears below the cell; a later cell can use variables defined in earlier cells that have already run.

3. Working with text: classes and methods

A class defines a kind of object and the behavior available to it; a particular value created from that class is an instance. You will use many existing Python classes even if you rarely write your own. An attribute is information attached to an object; a method is an operation associated with an object and called with dot notation.

For example, a string is a Python object, and string methods help inspect or transform text:

raw_name = "  Mina Patel  "
clean_name = raw_name.strip()
lower_name = clean_name.lower()
words = clean_name.split()

print(clean_name)  # Mina Patel
print(lower_name)  # mina patel
print(words)       # ['Mina', 'Patel']
  • isalpha() checks whether characters are letters (and requires at least one letter).
  • isdigit() checks whether characters are digits.
  • isupper() and islower() check letter case; non-letter characters are ignored, but there must be at least one letter.
  • upper(), lower(), and capitalize() return text with changed capitalization.
  • split() separates a string into a list, by default at whitespace; replace(old, new) substitutes text; strip() removes leading and trailing whitespace.

Strings are immutable: these methods return results rather than changing the original string in place. Save the returned result if you want to use it later. The demo also introduces encoding: encode("utf-8") converts text to bytes, and decode("utf-8") converts those bytes back to text.

Class detail: attributes can belong to a class or to an individual instance; they are not necessarily shared among all instances. For this lesson, focus on recognizing that objects have data and behavior, and that methods are called like text.strip().

4. Functions: name a reusable task

Python has built-in functions such as print(), int(), and round(). You can also define a custom function with def. Inputs are called parameters; return sends a result back to the code that called the function.

def classify_wait(minutes):
    if minutes is None:
        return "missing"
    elif minutes <= 20:
        return "on time"
    else:
        return "delayed"

status = classify_wait(18)
print(status)  # on time

The parameter minutes is local to the function call. The indented lines form the function body. In Python, indentation is required to show which statements belong to the function or branch; use consistent indentation (commonly four spaces)—a tab character is not required.

Print vs. return: print() displays something for a person to see; return gives a value back so other code can store or use it. A function that reaches its end without a return statement returns None.

5. Conditions: choose what happens next

An if/elif/else block checks conditions from top to bottom. The first true branch runs; else, if present, is the fallback if none of the earlier tests matched. elif and else are optional, but neither can replace the initial if.

rating = 3

if rating >= 4:
    label = "positive"
elif rating == 3:
    label = "mixed"
else:
    label = "negative"

Conditions evaluate to truth values. Useful operators include:

For example, number % 2 == 0 tests whether an integer is even. A remainder of 0 means it divides evenly by 2.

Assignment vs. comparison: a single = assigns a value, as in rating = 3. A double == asks whether two values are equal. Also, None is not the same value as False, even though both are treated as false in a conditional.

Python also treats some values as false in a condition: False, None, numeric zero, and empty collections or strings. Most other values are true. When learning, writing an explicit comparison often makes the intention clearer.

6. Loops: repeat work over items

A loop repeats a block of code. A for loop visits each item in an iterable—such as a list, string, dictionary, or a sequence made by range(). The loop variable is a temporary name for the current item.

order_ids = ["A12", "B03", "C19"]

for order_id in order_ids:
    print(f"Checking order {order_id}")

range(start, stop) provides integers from start up to, but not including, stop. For example, range(3) produces 0, 1, and 2, so the loop runs three times.

Use conditions inside a loop

Combining a loop with a branch allows a script to handle records differently. For a dictionary, test whether a key exists before trying to retrieve it, or use a deliberate missing-value strategy.

Loop-control statements

StatementEffectWhen it helps
passDoes nothing at that point; execution continues with the next statement in the same block.A temporary placeholder where Python syntax requires a statement.
continueSkips the remainder of the current iteration and moves to the next item.Skip an unusable record while continuing the batch.
breakExits the nearest enclosing loop immediately.Stop searching once the needed item is found, or end a bounded test early.

A while loop repeats while its condition remains true. Use it when the stopping point depends on a changing condition rather than a fixed collection. Ensure that the loop can eventually stop. try/except is a separate error-handling structure, not a kind of loop control; use it to respond to expected errors. exit() ends a program or interactive session, rather than merely skipping or breaking a loop.

7. Everyday example: checking delivery wait times

Illustrative example—not a course measurement. A café manager wants to label a small batch of delivery records. For this simple example, assume 20 minutes is the manager’s chosen on-time cutoff; it is not a universal service standard.

deliveries = [
    {"order": "A12", "minutes": 18},
    {"order": "B03", "minutes": 27},
    {"order": "C19", "minutes": None},
    {"order": "D08", "minutes": 22},
]

def classify_wait(minutes):
    if minutes is None:
        return "missing"
    elif minutes <= 20:
        return "on time"
    else:
        return "delayed"

for delivery in deliveries:
    minutes = delivery["minutes"]
    if minutes is None:
        print(f'{delivery["order"]}: no wait time recorded')
        continue
    status = classify_wait(minutes)
    print(f'{delivery["order"]}: {status} ({minutes} minutes)')

What is happening: the list holds the records; the function applies one consistent rule; the if checks for missing data; continue skips the rest of that iteration for the missing record; and the for loop repeats the process for each delivery.

Expected output for the invented example: A12 is on time; B03 is delayed; C19 has no wait time recorded; D08 is delayed. Changing the cutoff changes the labels.

8. Simulation: use a loop to explore uncertainty

A simulation repeats a simple random experiment to create synthetic observations. In the course demo, a random number is used to represent a fair coin flip, with heads coded as 1 and tails as 0. The mean of a list of 1s and 0s is the fraction of flips that were heads.

import random

flips = []
for _ in range(1000):
    flips.append(1 if random.random() < 0.5 else 0)

heads_fraction = sum(flips) / len(flips)
print(f"Heads: {heads_fraction:.1%}")

This uses Python’s standard random module as an illustrative equivalent to the course notebook’s NumPy random-number example. Each run can give a different percentage; the code does not promise exactly 50%. A fixed random seed can make a pseudo-random run repeatable for debugging.

Independent events and the gambler’s fallacy

For a fair coin, each toss is independent: the chance of heads on the next toss is still 50%, even after several heads in a row. The expectation of about half heads over a large number of tosses does not mean the next toss must “make up” for an earlier imbalance.

Runs of repeated outcomes do occur by chance. Seeing a streak is not, by itself, evidence that a coin is unfair. The demo explores comparing each toss with the one before it; in a more careful simulation, group observations by the previous outcome and compare the next-outcome proportions over many trials.

Probability caveat: the chance of one specific sequence of five tosses (for example, H-H-H-H-H) is 1/32 for a fair coin. The chance of either all heads or all tails in five tosses is 2/32 = 1/16. Those are probabilities for a particular five-toss window—not the probability of observing at least one five-in-a-row streak somewhere across 1,000 tosses, which is much larger. A streak threshold is not a sound fairness test by itself.

The course’s loop uses a counter of repeated matches after the first toss and checks when that counter reaches five; that corresponds to six identical tosses in a row, not five. Define whether a counter means “items in a streak” or “matches after the first item” before choosing a threshold.

9. Common mistakes and good habits

  • Forgetting indentation: indentation determines which statements belong to a function, condition, or loop. Keep it consistent.
  • Confusing = and ==: one assigns, two compare.
  • Assuming indexing starts at 1: Python sequence positions start at 0. In a slice such as items[0:2], the start is included and the stop is excluded.
  • Expecting a method to modify immutable text: save the result of strip(), lower(), or replace() if you want to keep it.
  • Using a missing dictionary key without checking: direct lookup raises KeyError when the key is absent. Check first or use a suitable lookup method.
  • Mixing up pass, continue, and break: no-op, skip this iteration, and leave the loop are different actions.
  • Writing a loop that never stops: a while loop needs a condition that can eventually become false, or an intentional stop mechanism.
  • Trusting a single random run too much: random variation is expected, and a sample outcome does not prove a process is fair or biased.
  • Confusing demonstration output with a guaranteed result: random outputs vary between runs unless a seed and implementation are fixed.

10. Quick recap

  • Use built-in functions and object methods to inspect, format, or transform values.
  • Use a custom function to give a repeatable task a name, accept inputs, and return a useful result.
  • Use if/elif/else to choose a path based on conditions.
  • Use for to process items in an iterable; use while when repetition depends on a condition.
  • Use continue to skip one iteration, break to exit a loop, and pass as a no-op placeholder.
  • Use simulations to explore uncertain scenarios, but interpret random outcomes with probability in mind.

11. Self-check

Try to answer each question before expanding the explanation.

1. What is the difference between print() and return in a function?

print() displays text or a value. return gives a value back to the caller so the program can store or use it.

2. In if number % 2 == 0:, what is being tested?

The remainder after dividing number by 2 is tested for equality with zero. That is a common way to test whether an integer is even.

3. What does continue do inside a for loop?

It skips the remaining statements in the current iteration and advances to the next item.

4. If a loop is written as for i in range(4):, how many times does it run?

Four times, with i taking the values 0, 1, 2, and 3. The stop value 4 is excluded.

5. Does a streak of heads make tails more likely on the next toss of a fair coin?

No. Under the fair, independent-coin assumption, the next toss remains 50% heads and 50% tails.

6. Why check whether a value is None before comparing it with a number?

None means no value is available. A numeric comparison with it is not the same as testing a number and can raise a type error. Handle missing data explicitly.

7. In the delivery example, what happens to the record whose minutes value is None?

The loop prints that the time is missing, then continue skips the classification and output steps for that record and proceeds to the next delivery.

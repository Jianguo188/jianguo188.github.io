M29: Transformers and NLP Applications

Transformers are neural-network architectures that use attention to connect words across a passage. This guide explains the core idea, how encoder and decoder components differ, and how pre-trained transformer models can be adapted to practical language tasks.

Learning goals: distinguish transformers from earlier neural-network approaches; explain attention, position, context, encoders, and decoders in plain language; and identify ways transfer learning can support text classification, masked-word prediction, semantic similarity, and text generation.

1. The big picture

Earlier neural networks can learn useful patterns, but language depends on relationships between words. The meaning of a word can depend on another word far away, not just on its immediate neighbors. Transformers use self-attention to let each token take relevant information from other tokens in the sequence. They add information about token position so order still matters.

A transformer can turn tokens into context-aware representations (often called embeddings). Depending on its architecture and task, it can use those representations to classify text, compare passages, fill in masked words, or generate output text.

Memory cue: attention asks “which other words matter here?”; positional information says “where was this word?”; contextual representations combine the two.

2. Key terms in plain language

Token

A unit of text processed by a model. A token may be a whole word, part of a word, or punctuation; it is not always identical to a word.

Attention

A learned way for the model to weight information from other tokens when building a representation. It helps capture useful relationships across a sequence.

Positional information

A signal that tells the model where tokens appear. Attention alone does not automatically mean “first,” “next,” or “last”; position helps preserve order information.

Embedding

A numeric representation of a token or text. In a contextual model, a token’s representation can reflect the surrounding passage, so the same word can be represented differently in different contexts.

Encoder / decoder

An encoder builds representations from input. A decoder uses representations and its permitted context to produce output, often token by token.

Transfer learning

Reusing a model that has already learned broad patterns from data, then adapting it to a more specific task. This can reduce the task-specific training burden, but does not eliminate the need for validation.

3. How attention builds context

Consider: “The black cat sat beside the heater because it was cold.” To understand it, a reader uses the rest of the sentence. To understand black, the nearby word cat is informative. For other words, useful clues may appear farther away. Attention gives a model a way to learn which parts of the input help interpret each token.

In simplified terms, each token can gather a weighted mixture of information from other tokens. The model learns these weights during training; they are not a manually written grammar rule, and attention weights should not automatically be treated as a complete explanation of the model’s reasoning.

Traditional neural networks can also learn interactions and some forms of context. The distinction emphasized in the lesson is that self-attention supports direct relationships between tokens across a sequence and permits parallel processing of the input tokens in ways that recurrent, step-by-step processing does not.

4. Encoders and decoders

Encoder: understand the input

An encoder turns input tokens into contextualized representations. The lesson highlights self-attention plus a feed-forward neural network with nonlinear activations. Encoder layers are commonly stacked so later layers can build on earlier representations.

Intuition: read a passage and create a context-aware representation of its parts.

Decoder: produce an output

A decoder generates output using masked self-attention, feed-forward layers, and—when paired with an encoder—attention to the encoder’s output. Decoder layers can also be stacked.

Intuition: produce the next output token using earlier output and, for encoder-decoder models, the input representation.

Why mask future tokens?

When generating a sequence from left to right, a decoder must not peek at the answer tokens that come later. Masked self-attention blocks access to future positions at each prediction step, so the model learns to predict using only the permitted past context.

How does encoder-decoder attention help?

In a sequence-to-sequence task such as translation, the decoder can attend to the encoded input while it produces each output token. This helps keep the output connected to the source sentence rather than relying only on previously generated words.

5. Worked example: translating a sentence

Illustrative explanation following the lesson’s translation example. Suppose the input is “I am wearing a jacket because I am cold.” A translation system must preserve the relationship between being cold and wearing a jacket, even though the relevant clue is not simply the word beside jacket.

  1. Tokenize the English input and add position information.
  2. Encode it: self-attention allows representations to draw on words elsewhere in the sentence; feed-forward layers further transform those representations.
  3. Begin the target sentence: a decoder predicts a target-language token while attending to the encoded input.
  4. Continue token by token: masked attention prevents each step from using target tokens that have not been generated yet.
  5. Stop at an end marker: the completed output is a model prediction, which may need evaluation or human review.

Position matters because word order and grammatical roles differ across languages. Context matters because a good translation aims to preserve meaning, not simply substitute isolated words one by one.

6. Transfer learning: adapt a pre-trained model

Training a large language model from scratch requires substantial data and computing resources. With transfer learning, start from a model that has already learned general language patterns, add or adapt a task-specific output layer, then fine-tune it on examples for the task.

5. Evaluatetest on separate examples

For a sentiment classifier, the model might output one score per label (for example, positive, neutral, and negative). Training adjusts the model so its predictions better match labeled examples. The lecture notes that relatively small labeled samples can sometimes be useful for fine-tuning a model whose parameters were pre-trained on much more text; the amount needed depends on the task, data quality, label consistency, and evaluation requirements.

BERT means Bidirectional Encoder Representations from Transformers. It is an encoder-based, pre-trained model. Derivatives and related models include DistilBERT, which is designed to be smaller/faster, and RoBERTa, which changes aspects of BERT’s pre-training recipe.

7. Four NLP application families

TaskPlain-language goalExample usesTypical model idea
Text classification Assign a label to a passage. Review sentiment, support-ticket topic, spam detection, news category. Use an encoder representation with a classification head, then fine-tune with labeled examples.
Masked language prediction Estimate which token could fit a blank given its context. Explore likely completions, flag unusual text, or study language patterns. Mask a token and score candidate replacements from context.
Semantic similarity Estimate whether two passages express related meaning. Find near-duplicate documents or candidate matches for review. Compare contextualized text representations using a suitable similarity method.
Text generation Produce a continuation or response from a prompt. Draft a reply, answer a question, or translate text. Usually use a decoder-only model or an encoder-decoder sequence-to-sequence model.

Named entity recognition (NER) is related to classification but typically predicts labels for individual tokens or spans—such as person, organization, or location—rather than one label for the whole passage.

Masked language example: in “I commonly drink [MASK] in the morning,” a model can rank possible words using the sentence context. A model’s ranking reflects patterns in its training and is not proof that a candidate is factually appropriate for a particular person.

Similarity models can help shortlist possible duplicate or similar passages, but similarity scores do not by themselves prove plagiarism or identical meaning. A person should review consequential matches.

8. BERT, GPT, and text generation: an important distinction

BERT is an encoder-only transformer, trained with objectives such as predicting masked tokens from surrounding context. It is especially useful as a foundation for language-understanding tasks, such as classification or extracting contextual representations.

GPT-style models are generally decoder-only transformers trained to predict the next token. Encoder-decoder models are another common design for input-to-output tasks such as translation or summarization. These architectures are naturally suited to generating sequences.

Clarifying the lecture: the applications slides list text generation in their overview of transformer uses and mention BERT in broad terms. In common architecture usage, BERT itself is not a standard free-form text generator; its encoder design is mainly for understanding and prediction tasks. For generation, decoder-only GPT-style or encoder-decoder models are the more typical choice.

Generated text is a model prediction based on learned patterns, not a guarantee of truth, expertise, or fresh information lookup. It can sound confident while being incorrect. Check outputs against trusted sources when accuracy matters.

9. Practical real-world example: sorting customer support messages

Illustrative scenario—not a result measured in the course. A retailer wants to route incoming messages to “delivery,” “returns,” or “product question.”

  1. Define the label scheme. Decide what each category means and how to handle messages that fit more than one category.
  2. Create labeled examples. Review a sample of messages and assign labels consistently. Record uncertain cases for discussion rather than hiding ambiguity.
  3. Choose an encoder model. Start from a suitable pre-trained language model such as a BERT-family encoder.
  4. Fine-tune a classification head. Train on the labeled examples to predict the routing label from the message text.
  5. Evaluate on held-out messages. Check not only overall correctness but also errors by category. A rare but important “returns” category can be missed even when total accuracy looks high.
  6. Use human review where needed. Low-confidence or consequential cases can be escalated to a person; monitor quality as language and products change.

This example shows why pre-training helps but is not magic: the model still needs a clear objective, useful examples, reliable labels, appropriate evaluation, and oversight.

10. Limitations and common mix-ups

  • Attention is not human understanding. It is a learned computation for combining information; it does not guarantee reliable reasoning or factual knowledge.
  • More context does not remove bias. Models learn from training text, which can encode social stereotypes or historical imbalances. Masked predictions and downstream classifications can reproduce them.
  • Pre-trained does not mean ready for every task. The model may need task-specific fine-tuning, and performance must be checked on relevant data.
  • Small training samples do not guarantee good results. A small labeled sample can be a starting point, but performance depends on data quality, coverage, class balance, and task difficulty.
  • Similarity is not proof. A model can find semantically related text without proving copying, intent, or exact equivalence.
  • Encoder and decoder roles differ. BERT’s encoder is designed to build contextual representations; GPT-style decoder models and encoder-decoder models are more typical for generation.
  • Context windows are finite. A model can only use the tokens available to it under its design and input limits; “global context” means the sequence available to the model, not all knowledge everywhere.

11. Quick recap

  • Self-attention lets tokens draw on useful information from other tokens; positional information preserves sequence order.
  • Encoders build contextual representations. Decoders generate output, often one token at a time; masked attention blocks future target tokens.
  • Transfer learning adapts a pre-trained model to a specific task using task-specific examples.
  • Common application families include classification, masked-token prediction, semantic similarity, and text generation.
  • BERT is encoder-only and most directly associated with language-understanding tasks; GPT-style decoder-only and encoder-decoder models are common for generating text.
  • Models can be biased or wrong; use task-appropriate evaluation and human review for important decisions.

12. Self-check

Try each question before opening its explanation.

1. How does self-attention help a model interpret a word using distant context?

It allows the representation of one token to incorporate weighted information from other tokens in the available sequence, including tokens that are not adjacent.

2. Why does a transformer need positional information?

Attention combines token information but does not by itself encode the original order. Position information helps the model distinguish arrangements such as “dog bites person” from “person bites dog.”

3. What does the encoder usually produce, and what does a decoder do?

The encoder produces contextualized input representations. A decoder uses permitted context—and often the encoder output—to produce an output sequence.

4. What is the basic idea of transfer learning for sentiment classification?

Start from a pre-trained language model, attach/adapt a classification head, and fine-tune it using labeled examples that represent the sentiment task.

5. Why is “BERT is a text generator” an imprecise statement?

BERT is an encoder-only model primarily used to build contextual representations and support understanding tasks. Decoder-only GPT-style and encoder-decoder sequence-to-sequence architectures are more typical for free-form generation.

6. If two passages receive a high semantic-similarity score, what can you conclude?

They may be semantically related under that model and scoring method. The score alone does not prove plagiarism, exact equivalence, or that either passage is correct.

7. Name one risk of masked-language predictions.

Predictions can reflect biases and imbalances in the training text. They are model preferences, not objective facts about people or the world.

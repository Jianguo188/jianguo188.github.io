M2: Python Containers

Lists, sets, tuples, and dictionaries all hold other objects—but each is suited to a different job. This guide explains how to choose among them and how their behavior connects to real tasks.

1. The big picture

A container is an object that holds other objects. Think of containers as different organizers: a numbered list, a unique-item basket, a fixed record, or a labeled filing cabinet. The best choice depends on what you need to do with the information.

Four basic questions help you choose:

  1. Can the collection change after it is created?
  2. Does the order matter?
  3. Do you need to retrieve an item by its position, by a key, or just check whether it is present?
  4. Will the container itself (or one of its items) need to serve as a dictionary key or set member?
Memory cue: list = sequence, set = unique membership, tuple = fixed record, dictionary = key-to-value lookup.

2. Key terms in plain language

Mutable

The object can be changed in place after it is created. Lists, sets, and dictionaries are mutable. Immutable does not mean a variable can never be assigned a new value—it means the existing object cannot be edited in place.

Ordered

The container preserves a defined iteration order. Lists and tuples follow their sequence order. Modern Python dictionaries preserve insertion order (a language guarantee since Python 3.7). Sets are unordered, so do not rely on their iteration order.

Indexing

Accessing an item by its position, often with square brackets such as items[0]. Lists and tuples use integer positions starting at 0. A dictionary uses keys for lookup; a set has no positional indexing.

Hashable

An object is hashable when it has a hash value that stays consistent during its lifetime and can be compared for equality. Hashable values can be dictionary keys and set elements. Common examples include strings, integers, and tuples whose contents are all hashable.

Hashability clarification: the slide describes hashability as having a “static address.” That is a simplified and potentially misleading metaphor: hashability is about a stable hash value, not a fixed memory address. Mutability is a useful clue, but the key test is whether the object’s hash and equality behavior remain suitable for lookup. A tuple is hashable only if all of its elements are hashable.

3. Compare the four built-in containers

TypeTypical syntaxMutable?Order / accessGood forHashable?
List [a, b, c] Yes Ordered; integer-indexed A sequence that may change or contain duplicates No
Set {a, b, c} Yes Unordered; no positional indexing Unique values and membership checks No
Tuple (a, b, c) No Ordered; integer-indexed A fixed sequence or multi-part key Yes, if every item is hashable
Dictionary {key: value} Yes Insertion-ordered; access by key Associating labels/keys with values No

A dictionary is ordered in the sense that iteration follows insertion order, but it is not a positional sequence: use a key such as "name" rather than assuming an integer position. Dictionary keys must be unique and hashable; values can be objects of many types, including mutable ones.

Set elements and dictionary keys need to be hashable. Lists and dictionaries cannot be used as set elements or dictionary keys. A tuple can be used when all of its contents are hashable.

4. Real-world example: packing for a weekend trip

Illustrative example, not a measured result from the course. Suppose you are organizing a travel checklist, tracking unique destinations, representing a booking identifier, and looking up booking details.

List: checklist in sequence

Keep tasks in the order you plan to do them, and add or remove items as plans change.

packing = ["passport", "charger", "jacket"]
packing.append("toothbrush")
first_item = packing[0]

Set: unique destinations

Store each destination once, even if it appears repeatedly in the itinerary. Ask quickly whether a place is already included.

cities = {"Oslo", "Bergen", "Oslo"}
# cities contains each value once
already_planned = "Bergen" in cities

Tuple: multi-part identifier

Pair a confirmation code with a year to form one fixed, hashable key, assuming both parts are hashable.

booking_key = ("AB123", 2026)

Dictionary: details by key

Look up booking details using a meaningful label or identifier. Each key maps to a value.

booking = {
    "traveler": "Mina",
    "city": "Oslo",
    "nights": 2
}
city = booking["city"]

The examples show typical uses. In real programs, choose keys and data fields that make the information clear and avoid storing unnecessary personal details.

5. Useful syntax details

  • List: square brackets. Positions start at zero: the first item is items[0].
  • Set: braces with comma-separated values. To create an empty set, use set(); {} creates an empty dictionary. Sets keep distinct elements, not duplicates.
  • Tuple: often written with parentheses, but the commas make it a tuple. A one-item tuple needs a trailing comma: ("Oslo",). ("Oslo") is just a string in parentheses.
  • Dictionary: braces with key: value pairs. If the same key is assigned again, its value is replaced; keys do not appear twice as separate entries.
  • Nested containers: lists, tuples, sets, and dictionaries can hold other objects, subject to the hashability requirement for set elements and dictionary keys.
Example of immutable reassignment: if place = ("Oslo", 2026), you cannot change one element of that tuple in place. You can assign a different tuple to the variable place; that replaces the variable’s reference rather than editing the original tuple.

6. Which container should you choose?

If you need to…Consider…Why
Keep an ordered, editable sequence, possibly with repeated itemsListIt is ordered, indexable, and mutable.
Remove duplicates or test whether a value is presentSetValues are unique; membership checks are a core use. Average membership performance is typically efficient, but exact speed depends on details.
Keep a small, fixed sequence, or use multiple values as one keyTupleIt is ordered and immutable; it is hashable when its contents are hashable.
Look up a value from a meaningful keyDictionaryIt maps unique hashable keys to values.

For example, the lecture describes using a tuple like ("Microsoft", 2010) to identify one company-year record. That tuple can serve as a dictionary key if both parts are hashable:

annual_data = {
    ("Microsoft", 2010): {"revenue": 62.5},
    ("Microsoft", 2011): {"revenue": 69.9}
}
record = annual_data[("Microsoft", 2010)]

The revenue figures above are fabricated solely to illustrate the data structure; they are not course results or verified financial figures.

7. Containers beyond Python’s built-ins

  • collections: provides specialized container tools. For example, Counter is useful for counting occurrences, and defaultdict can provide a default value for a missing key.
  • NumPy: provides arrays and tools for numerical and scientific computing, including vectorized operations and linear algebra.
  • pandas: provides tools for working with structured, tabular data. A pandas DataFrame is a common target when converting unstructured material into rows and columns.

These tools build on ideas from basic containers, but they have specialized behavior and operations. Learn the four built-in types first, then use additional packages when their features fit the task.

8. Common mix-ups and limitations

  • Parentheses do not automatically make a tuple. It is the comma that forms a tuple; remember the comma in a one-item tuple.
  • Curly braces are shared syntax. Non-empty {1, 2} is a set; {"a": 1} is a dictionary; empty {} is a dictionary.
  • Ordered is not the same as integer-indexed. A dictionary preserves insertion order, but its normal lookup is by key. A set has no guaranteed order.
  • Immutable does not always mean hashable. A tuple containing a list cannot be hashed, because the list is unhashable. Tuple hashability depends on its contents.
  • A hashable tuple can still contain mutable-looking data? Check every item. For example, a tuple containing only strings and numbers is hashable; a tuple containing a list is not.
  • Sets discard duplicates and do not preserve a usable position. If order or repeated values matter, use a list instead.
  • Container choice is task-dependent. A list is flexible, but a dictionary or set may describe the relationship or membership question more directly.

9. Quick recap

  • List: mutable, ordered, indexable sequence; duplicates allowed.
  • Set: mutable collection of unique hashable elements; unordered and not indexable.
  • Tuple: immutable, ordered, indexable sequence; hashable only if every element is hashable.
  • Dictionary: mutable mapping of unique hashable keys to values; preserves insertion order in modern Python.

Choosing a container thoughtfully makes code clearer and helps prevent errors when you update data, test membership, or use keys.

10. Self-check

Try each question before opening its explanation. The answers use keyboard-accessible expandable sections.

1. You need an editable checklist where order matters and the same item may appear twice. Which container fits?

A list: it is mutable, ordered, indexable, and permits repeated values.

2. What is the result of writing {} when you intend to make an empty set?

{} creates an empty dictionary. Use set() for an empty set.

3. Can ("trip", [2026]) be used as a dictionary key?

No. The outer object is a tuple, but one of its elements is a list, which is unhashable. A tuple is hashable only when all of its contents are hashable.

4. A dictionary remembers the order keys were inserted. Can you use my_dict[0] to get its first inserted value?

Not reliably as “the first item.” Square-bracket dictionary access looks up a key. Use the actual key, or explicitly iterate over items if you need to work with insertion order.

5. Which container is a natural fit for counting how many times each word appears?

A dictionary can map each word to its count; collections.Counter is a specialized tool for this pattern.

6. What does hashable mean, and why does it matter for dictionary keys?

A hashable object has a stable hash value during its lifetime and equality behavior suitable for lookup. Dictionaries use hashes to find keys efficiently, so a key must not change in a way that invalidates its lookup.

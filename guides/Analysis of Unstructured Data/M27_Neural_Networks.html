M27: Neural Networks

1. The big idea

An artificial neural network (ANN) learns combinations of input features that help predict an outcome. It does this by passing signals through connected layers and adjusting the strengths of those connections using examples.

The “neural” name is an inspiration, not a claim that a computer network works just like a human brain. For this lesson, think of it as a flexible mathematical model made of layers of simple computations.

Deep learning refers broadly to learning with multiple layers and nonlinear transformations. More layers can model more complex patterns, but they also add parameters and training demands. A deeper model is not automatically better for every dataset.

Learning roadmap: represent the input as numbers → pass it through the network → compare its prediction with the known answer → adjust weights → repeat → check performance on examples not used for fitting.

2. The three parts of a basic network

Input layer

Receives the model’s features. Its size is determined by the shape of the input data—for example, the number of columns in a document-term matrix or the dimensions in an embedding.

Hidden layer(s)

Transform and combine input signals. The analyst chooses how many hidden layers and how many nodes each layer has. More nodes and layers mean more trainable parameters.

Output layer

Produces the model’s prediction. Its design depends on the task: one numeric prediction for a single regression outcome, or outputs corresponding to the classes in a classification task.

For example, a three-class sentiment task might produce scores for negative, neutral, and positive. The output structure should match the prediction the model is meant to make.

Size is a design choice, not a magic formula. The lecture recommends starting relatively small and expanding if needed, considering the amount and shape of the available data.

3. What happens inside one node?

A node receives values from the previous layer. It multiplies each input by a learned weight, adds a bias, then applies an activation function.

node output = activation(weighted sum of inputs + bias)

Weights control how strongly inputs influence the node. A bias works like an adjustable intercept, shifting the combined signal. The activation function shapes the signal before it moves to the next layer.

Two activation functions introduced in the lesson
FunctionSimple descriptionCommon intuition
ReLU Returns 0 for negative input and returns the input itself for positive input: max(0, z). Lets positive signals through while setting negative signals to zero.
Sigmoid Maps a value to a number between 0 and 1. Can express a binary-class score as a probability-like value; it is often used for a binary output.
Linear Applies no nonlinear transformation to the weighted sum. Useful in some outputs, but stacking only linear transformations does not create the same nonlinear flexibility.

Nonlinear activations allow networks to learn relationships more complex than a single linear rule. Activations at hidden layers and the output function serve different purposes; choose them to fit the task.

4. How the network learns

  1. Initialize weights. The network starts with initial values for its weights and biases, commonly chosen using a randomized initialization scheme.
  2. Make a forward pass. Send input examples through the layers to get predictions. Training may process examples in small groups called batches.
  3. Measure the error. A loss function quantifies how far predictions are from the known training answers.
  4. Compute gradients. A gradient describes how the loss would change as the weights change.
  5. Update weights with backpropagation and an optimizer. Backpropagation uses the error information to calculate how weights contributed to the loss; an optimization method adjusts them to reduce it. The learning rate controls the size of updates.
  6. Repeat and monitor. Continue over batches and epochs, checking validation performance and stopping or changing settings as appropriate.
Epoch
One complete pass over the training dataset.
Batch
A group of examples processed together before an update. In stochastic gradient descent, the batch size is one example.
Hyperparameter
A setting selected by the practitioner, such as layer sizes, learning rate, batch size, or number of epochs.
Validation set
Held-out examples used to monitor how the model performs beyond the examples it is fitting on.

Training examples teach the model; validation examples help reveal whether it is generalizing or simply getting better at the training data. An evaluation metric should reflect what matters for the task.

5. What is different when the inputs are text?

A neural network cannot directly learn from ordinary sentences as strings. Text must first be represented numerically, and design choices affect what the model can learn.

Text representation

Bag-of-words and TF-IDF create document-term features, but they do not inherently preserve word order or context. Embeddings represent words or larger text units as dense vectors and can encode semantic relationships. Select a representation that fits the task.

Scope and sequence length

Decide whether one example is a full document, paragraph, sentence, or another unit. Some architectures expect a fixed number of tokens; shorter sequences may be padded and longer ones truncated. Truncation can discard useful information.

Casing and preprocessing

Lowercasing can simplify text, but retaining case may help distinguish names or other meaningful patterns when there is enough data. Preprocessing should be chosen for the problem, not applied blindly.

Architecture

Different architectures suit different patterns. The lesson notes recurrent approaches such as LSTMs and GRUs for sequence-dependent tasks and transformers for modeling broad token relationships. This lesson introduces the considerations; later Week 7 lessons cover transfer learning and transformers.

Text representations can be very wide, and the number of model parameters can grow quickly. Consider data volume, memory, compute time, and whether a pretrained model or transfer learning is a more suitable route than training a large model from scratch.

6. Worked real-world example: routing customer feedback

Illustrative example—not a measured result from the course materials.

Suppose a service company wants to send customer messages to one of three teams: billing, delivery, or technical support.

  1. Collect examples and labels. Gather past messages with reliable team labels. The model learns from these examples, so unclear or inconsistent labels can limit its performance.
  2. Represent each message. Convert text into features such as term counts or embeddings. A basic document-term matrix might have thousands of columns; the input layer reflects the chosen feature shape.
  3. Choose a small initial network. Feed the input features through one or more hidden layers. Each node combines signals using weights and biases, with nonlinear activations.
  4. Produce class outputs. Set up the output for the three routing categories. Train using known labels and an appropriate loss function.
  5. Check unseen cases. Use validation data and a relevant metric. Review mistakes, especially cases where an incorrect route could create delays or harm customers.
  6. Monitor fairness and changes. Check whether the model performs differently across language styles or customer groups, and revisit it as new types of requests appear.

If a message says “I was charged twice, and my package is late,” a single-label model may need a routing rule for mixed issues. That is not solved merely by adding more layers: it is a question about the task definition and labels.

7. Data, computation, and model fit

  • Model complexity: adding layers or nodes increases the number of weights to learn. With limited examples, an oversized network can memorize training data rather than generalize.
  • Overfitting: performance looks strong on training data but weaker on new examples. Validation monitoring and regularization methods such as dropout or weight decay can help, though they do not guarantee a good model.
  • Computing resources: large models and high-dimensional text features can demand substantial memory and processing. GPUs can speed up many parallel computations, but resources still matter.
  • Metric choice: choose evaluation measures based on the real cost of errors. Accuracy alone can be misleading when classes are imbalanced or some mistakes matter more.
  • Training from scratch vs. transfer learning: training a complex language model from scratch can require substantial data and compute. A pretrained model can begin with learned language patterns and be adapted to a specific task; this is introduced in the next lesson, not the focus of this guide.

8. Ethical use and careful interpretation

  • Training data can carry social bias. If some groups or language varieties are underrepresented, model performance may be uneven. Patterns in the text can also lead to problematic associations.
  • Define the purpose and consequences. Ask who may be affected by a prediction and what happens when it is wrong.
  • Review features and preprocessing thoughtfully. Decide whether names or sensitive attributes should be included, masked, or separately audited. Removing an obvious word does not necessarily remove all related bias.
  • Check labels. Noisy or subjective labels teach the model the labeling process, not necessarily the concept you intended.
  • Probe behavior. Inspect feature influences where possible and test carefully designed example sentences that might reveal unwanted associations.
  • Remember that scores are uncertain. A model often produces scores or probabilities; turning them into a fixed class requires a threshold or decision rule and should not hide uncertainty.
Practical principle: neural-network predictions are evidence to review, not automatically objective facts. A high score does not fix biased data, unclear labels, or a poorly chosen task.

9. Quick self-check

1. What determines the input layer’s size?

The shape of the numeric input representation—for example, the number of features or dimensions passed into the model.

2. What does a node do with its inputs?

It combines weighted inputs with a bias, then applies an activation function.

3. In plain language, what is backpropagation for?

It traces how prediction error relates to the network’s weights so an optimizer can adjust those weights to reduce the loss.

4. Why use a validation set?

To monitor performance on examples not used to fit the model and help identify overfitting or guide model choices.

5. What can bag-of-words miss compared with contextual representations?

Basic bag-of-words features do not inherently retain token order or contextual meaning; embeddings can encode richer semantic relationships.

6. Why is starting with a small model often sensible?

A smaller model can reduce unnecessary parameters, training time, and overfitting risk when data is limited; increase complexity only when evidence supports it.

7. Name one way bias can enter an NLP model.

Training data may underrepresent some people or language varieties, or contain repeated social associations that the model can learn and reproduce.

10. Takeaway

  • An ANN has input, hidden, and output layers; the input and output shapes depend on the data and task.
  • Nodes combine inputs through learned weights and biases, then apply activations.
  • Training uses predictions, loss, gradients, and weight updates; validation checks generalization.
  • NLP requires deliberate choices about text representation, casing, unit of analysis, sequence length, and architecture.
  • Complexity, compute limits, label quality, bias, and uncertainty all matter—not only predictive performance.
